How to compile packJPG
~~~~~~~~~~~~~~~~~~~~~~

This document gives instructions on compiling packJPG either as an
executable or as a static/shared library. A C++17-capable compiler is
required (e.g. GCC 7+, Clang 5+, AppleClang, MinGW-w64, or MSVC 2017+).


Compiling packJPG as an executable
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

A single cross-platform 'Makefile' is provided in the 'source' directory
for Linux, macOS, and Windows (MSYS2 / MinGW-w64):

  Linux / macOS:
    make -C source
    make -C source install PREFIX=/usr/local   # optional install

  Portable static Linux binary (requires static libc/libstdc++):
    make -C source STATIC=1

  Windows (MSYS2 MINGW64 / MINGW32 or MinGW-w64):
    make -C source                             # or mingw32-make -C source

  Optional UPX executable compression (requires 'upx' in PATH):
    make -C source USE_UPX=1

On Windows, 'windres' compiles 'icons.rc' into 'icons.res' for the active
target architecture (32-bit or 64-bit).

To compile with Microsoft Visual Studio, create a C++ Console Application
project with C++17 enabled (/std:c++17) and add 'aricoder.cpp',
'bitops.cpp', and 'packjpg.cpp' (plus 'icons.rc' if desired).


Compiling packJPG as a static or shared library
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Note: Always run 'make -C source clean' when switching between executable,
'dev', 'lib', and 'dll'/'shared' targets so object files are rebuilt with
the matching preprocessor defines.

  Static library ('packJPGlib.a'):
    make -C source clean lib

  Shared library ('libpackJPG.so', 'libpackJPG.dylib', or 'packJPG.dll'):
    make -C source clean shared                # alias: make -C source dll

When building with another build system or IDE:
- Define 'BUILD_LIB' when compiling a static library (include 'packjpglib.h'
  in consumer projects).
- Define 'BUILD_DLL' (which also implies 'BUILD_LIB') when compiling a
  shared library (include 'packjpgdll.h' in consumer projects).


Compiling developer functions
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

To include developer/debugging functions in the packJPG executable:

    make -C source clean dev

This defines 'DEV_BUILD'. Developer functions are not available in library
builds and are not needed for normal compression or decompression. Read
'developer.txt' for more information.


Defines overview / summary
~~~~~~~~~~~~~~~~~~~~~~~~~~

BUILD_LIB
Has to be defined when compiling a static or shared library.

BUILD_DLL
Has to be defined when compiling a shared library (implies BUILD_LIB).

DEV_BUILD
If defined, developer functions are included in the executable. In library
builds developer functions are not available.
